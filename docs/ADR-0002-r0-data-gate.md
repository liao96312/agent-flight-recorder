# ADR-0002：R0 数据门保持当前产品边界

- 状态：已接受
- 日期：2026-07-27
- 决策：`DEC-01`
- 证据：[R0-09 真实会话评审台账](./R0-09-OBSERVATIONS.md)（20/20）

## 决策

保持现有产品形态：`afr` CLI 是唯一证据内核，Codex Desktop 使用已交付的最小正式 Hook，Codex / Claude Code 继续共用薄 skill。

本数据门不启动新的 hooks、索引、团队汇总、签名、回放或来源格式升级。已定位且能安全修复的具体缺陷继续按现有架构修复；没有达到门槛的方向留在条件性 backlog。

## 证据判断

| 候选方向 | 重复证据 | 用户影响 | 本次判断 |
|---|---|---|---|
| 补更多宿主工具结果 | 7、8、9 的 Desktop session 均有 `tool_started/tool_finished` 缺口 | 报告只能诚实标记 `partial`，无法判断失败、取消、宿主未发送或采集丢失 | 不扩建。当前没有宿主提供而 AFR 未消费的确定事件，也没有三个因该缺口无法完成的具体复盘 |
| wrapper 事件压缩或索引 | 11、12、13 的短审查产生约 0.54–1.66 MB、602–3,041 events | 人工复核有噪声，但均在约 2–3 分钟完成，未出现扫描或浏览器性能失败 | 不加索引或批处理。现有有界报告足够，数据库没有被测量证明必要 |
| 敏感词上下文分级 | 5、12 确认受控源码/测试引用可触发 high | 会增加人工确认，但没有明文泄露；保守规则仍保护安全边界 | 不降低规则。缺少安全的上下文判定和用户误操作证据 |
| 构建来源身份 | 2、3、18 显示 PATH/版本漂移，dirty 二进制无法由 session 自证 | 本地开发台账需要操作者注明 dirty；正式 Release 已由 tag、commit、SHA 和回下载门槛覆盖 | 不升级 session 格式。当前缺口没有破坏正式发布追溯 |
| 团队汇总、签名、回放 | 20 条中没有多人汇总、高保证对抗或安全回放需求 | 没有已验证用户价值 | 保持暂缓 |

## 收益与成本

- 收益：避免为宿主缺失事件、尚未成为瓶颈的扫描和一次性来源问题引入新格式、数据库、后台服务或第二套证据逻辑。
- 成本：Desktop 工具结果仍可能是 `partial`；wrapper 原始事件仍偏大；本地 dirty 构建仍依赖操作者标注。
- 已接受原因：这些限制都已在报告或文档中明确，不会被误写为已观察或已证明。

## 非目标

- 不推断宿主没有发送的工具结果。
- 不为减少误报而保存原始秘密或降低写盘前脱敏。
- 不建设遥测、云后台、Dify、MCP、daemon、SQLite 或全文索引。
- 不在本决策中改变 Event v1、Manifest v1 或旧 session 的 verify 语义。

## 下一检查点

只有出现以下任一组新证据才重开一个方向；一次仍只启动一个：

1. 至少 3 个新的独立 Desktop session 因同一种工具结果缺口无法得出具体复盘结论，并且宿主存在 AFR 尚未消费的稳定事件。
2. 至少 3 个新的 wrapper session 因事件体积导致报告打开失败、扫描成为实测瓶颈，或人工复核仅因事件噪声超过 5 分钟。
3. 至少 3 个新的 high 误报导致错误处置，且能在不保留秘密、不降低默认保护的前提下稳定区分上下文。
4. 正式发布或高保证用户要求 session 自带可验证的二进制来源身份，而现有 tag、commit、SHA、CI 和回下载链路不足。

在触发前，正确动作是保持当前边界并继续收集本地、可定位的真实 session，而不是为了版本号扩张范围。
